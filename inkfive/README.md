# 墨水连珠 · Ink Five

画在作业本上的五子棋。**点一个格点落一枚手绘棋子**：蓝圆珠笔画 ○，红笔画 ✗，横竖斜任意方向先连成五子者胜。落在荧光格上还会触发道具，一步就能翻盘。鼠标和触屏都能玩，不需要键盘。

和合集里其它游戏一样：纯静态站点、无构建步骤；画面（棋盘、棋子、道具标记、胜利大勾）与 8-bit 音乐音效全部由 three.js + WebAudio 程序化生成，没有图片、模型或音频文件。联机走 WebRTC 点对点（PeerJS），不需要游戏服务器。

## 运行

```bash
python serve.py 8914
```

打开 http://127.0.0.1:8914。部署到任意静态主机即可联机游玩。

> 联机需要访问公共信令服务（PeerJS 云，默认 `0.peerjs.com`）。若所在网络无法访问，建房 / 加入房间会提示超时；单人模式不受影响。

## 操作

| 动作 | 鼠标 / 触屏 | 键盘 |
| --- | --- | --- |
| 落子 | 单击格点 | — |
| 请求悔棋 | 结算面板 / 见下方 | U |
| 暂停 / 菜单 | — | Esc |
| 音乐开关 | — | M |
| 重开本局 | — | R |

单机按 `U` 直接退回上一回合（撤销自己与 AI 各一手）；联机按 `U` 会发起**悔棋请求**，需要所有对手点「同意」才生效，任何一方拒绝即取消。

## 玩法

- **闯关**：8 关。前两关是「一步必胜」残局（棋盘上已有蓝四连 + 红笔干扰子），中间几关是空盘对局，道具格与 AI 搜索深度逐关增加；最后一关是**涂改液 Boss**，每 6 手擦掉你最近落的一颗子。赢一关解锁下一关，结算面板可直接点「下一关」继续（也可按 Enter 或点空白处），同时保留「重玩本关」；本地保存进度与累计胜场。
- **自由对局**：空盘开局，三档难度（简单 / 普通 / 困难）对应 AI 搜索深度 1–3。
- **联机**：1v1 或 2v2 轮流落子，座位顺序 `A1 → B1 → A2 → B2`（队伍分别为 `1,2,1,2`）。第 5 人起自动**观战**，中途加入也能看到当前棋局。支持公开房 / 私人房（5 位房间码）/ 快速匹配 / 悔棋协商。

## 四种道具

棋盘上带彩色小标记的格点就是道具格，落子到该格时触发并消耗：

| 标记 | 道具 | 效果 |
| --- | --- | --- |
| 黑色圆点 | 墨渍炸弹 | 清除落子点周围 3×3 内所有对手棋子 |
| 粉色方块 | 橡皮擦 | 擦掉对手最近落的一子 |
| 绿色三角 | 荧光笔 | 连击：本方立刻再下一手，不换执手 |
| 橙色圆环 | 回形针 | 冻结对手 2 回合的道具（落在道具格也不生效） |

判定顺序为「落子 → 判五连 → 结算道具 → Boss 擦子 → 判平局 → 轮换」，所以成五的一手直接终局，不会被道具反转。

## 规则与 AI

棋盘是 `15 × 15` 的格点。所有规则都写在 `src/rules.js` 的**纯函数**里：`applyMove(state, c, r, team)` 返回新状态与事件流，从不修改入参；单机 AI、房主校验和客户端回放共用同一份代码，不存在「单机合法、联机非法」的分叉。

AI 用 **minimax + α-β 剪枝**：评估函数扫描四个方向的连子段，按长度与两端开放度加权（活四 ≫ 冲四 ≫ 活三…）；候选只取已有棋子周围 2 格内的空点并按启发式排序，最多 9 个分支；另有节点预算上限，保证深度搜索也不会卡住页面。下子前先检查「一步必胜」和「必须堵住对手的一步必胜」，再进入搜索。道具格在候选排序里加权，但 AI 不预测道具连锁后果 —— 这是留给玩家的优势。

## 视觉

沿用 `doodletank` 的正交 `InkRenderer`（本作改成**正俯视**）：场景先渲进数据缓冲（明暗 / 墨色 id / 法线 + 深度），再由全屏 pass 画轮廓、排线、纸纹、横格线和红色装订线。星位与装订孔按墨色合并成少量 mesh；○ 是两道略微错开的圆环（像圆珠笔画了两次），✗ 是两片交叉细条，二者各用一个 `InstancedMesh`（225 实例）渲染，只有落子时才更新矩阵。道具标记按四种墨色各用一个实例网格。获胜时红色大勾横跨纸面，五连格高亮。

**棋盘网格与外框由后处理直接印在纸面上**（`uGridOn / uGridCell / uGridHalf / uGridPx`），线宽按像素固定为 1.5px 并由 `uRes / uHalf` 换算成世界宽度，因此 15×15 条线在任何窗口比例下都完整，也不进入深度缓冲。之前用 3D 细条实现过，问题有两个：细条在宽屏下会掉到亚像素而整条消失，加粗后又会被后处理的斜排线画成乱纹、交叉处还会 z-fighting；相机带俯角时细条侧面也会投影成第二根线。改成纸面绘制后这些都不存在，代价是网格没有立体厚度——对印在作业本上的棋盘来说反而更贴切。

## 技术架构

```
inkfive/
├── index.html          # importmap(three) + peerjs + canvas#c + #hud + main.js
├── style.css           # 作业本风格 UI
├── serve.py            # 本地静态服务器
├── Dockerfile / docker-compose.yml
├── vendor/             # three.module.js + peerjs.min.js
└── src/
    ├── main.js         # 状态机、菜单、单机/联机、单击落子、悔棋协商
    ├── rules.js        # 纯函数：落子、五连、道具、座位轮换、悔棋、RLE 编解码
    ├── board.js        # 手绘棋盘、○/✗ 实例化、道具标记、胜利大勾
    ├── levels.js       # 8 关配置、一步必胜残局生成、道具散布
    ├── ai.js           # minimax + α-β、候选剪枝、节点预算
    ├── hud.js          # 回合指示、道具图例、座位列表、菜单/结算
    ├── pointer.js      # 单击射线 → 格点
    ├── render.js       # 正交 InkRenderer（复用）+ 后处理绘制棋盘网格
    ├── effects.js      # 墨点/橡皮屑特效（复用）
    ├── audio.js        # 程序化 8-bit 音乐音效（复用）
    ├── net.js          # PeerJS 大厅与消息层（复用，独立命名空间）
    └── util.js         # 小工具（复用）
```

联机消息：`intent`（点击格点）/ `state`（房主校验后广播的完整 RLE 状态 + 事件流）/ `start`（开局或中途加入）/ `end` / `undoreq` / `askundo` / `undovote` / `undocancel` / `undodone` / `lobby` / `backtolobby`。棋盘只有 225 格，压缩后单条状态不足 1 KB，所以**每落一子发一次全量状态**即可，不需要 15Hz 快照或客户端插值。
