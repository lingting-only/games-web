# 盖章大战 · Stamp Duel

画在作业本上的**三车道印章塔防**。墨水会自己回满，攒够了就点己方半页的车道盖下一枚印章：单位自动沿车道推进，遇敌停下互射；谁先把对面的墨水瓶打爆谁赢。全程只需要单击，鼠标和触屏都能玩。

和合集里其它游戏一样：纯静态站点、无构建步骤；画面与 8-bit 音乐音效全部由 three.js + WebAudio 程序化生成，没有图片、模型或音频文件。联机走 WebRTC 点对点（PeerJS），不需要游戏服务器。

## 运行

```bash
python serve.py 8915
```

打开 http://127.0.0.1:8915。部署到任意静态主机即可联机游玩。

> 联机需要访问公共信令服务（PeerJS 云，默认 `0.peerjs.com`）。若所在网络无法访问，建房 / 加入房间会提示超时；单人模式不受影响。

## 操作

| 动作 | 鼠标 / 触屏 | 键盘 |
| --- | --- | --- |
| 部署一枚印章 | 点己方半页的任意一条车道 | — |
| 切换印章 | 点底部印章栏 | 1 / 2 / 3 / 4 |
| 暂停 / 菜单 | — | Esc |
| 音乐开关 | — | M |
| 重开本局 | — | R |

点击位置只决定**车道**和**是否为己方半页**；单位总是从己方阵地出发。墨水不足或刚盖过一枚（0.32 秒冷却）时会给出提示。闯关胜利后结算面板可直接点「下一关」，也可按 Enter 或点空白处续关。

## 四种印章

| 印章 | 消耗 | HP | 射程 | 伤害 / 间隔 | 定位 |
| --- | --- | --- | --- | --- | --- |
| 铅笔兵 | 2 墨 | 26 | 1.7 | 5 / 0.80s | 便宜快速，铺量 |
| 回形针弓手 | 3 墨 | 17 | 9.5 | 9 / 0.90s（发射纸团） | 远程输出，怕被贴脸 |
| 橡皮盾 | 4 墨 | 95 | 1.7 | 6 / 1.10s | 厚实肉盾，替后排挡刀 |
| 墨水瓶巨兽 | 6 墨 | 120 | 2.1 | 22 / 1.30s | 又慢又贵，用来打破僵局 |

数值按「每墨伤害」大致拉平，所以只铺最便宜的兵不是万能解：弓手输出更高但脆，肉盾能撑住战线，巨兽适合攒一波推平基地。

## 玩法

- **闯关**：10 关。前 3 关是教学（逐关解锁回形针弓手、橡皮盾、墨水瓶巨兽），之后涂改液怪的部署节奏、可用兵种与基地厚度逐关提升；**第 6 关起还会周期性「怪潮爆发」**，一次连出两枚印章（照样花墨水，只是忽略部署冷却）。敌方花的墨水和你同源，不作弊。赢一关解锁下一关，本地保存进度与累计胜场。
- **联机**：1v1 / 2v2。前 4 人按座位交替分队（蓝 / 红 / 蓝 / 红），**同队共享一座墨水瓶与一条墨水条**，谁都能在己方半页部署；第 5 人起自动观战。3 分钟到时按双方基地剩余血量比例判定。支持公开房 / 私人房（5 位房间码）/ 快速匹配 / 中途加入。

## 规则与敌方 AI

`src/rules.js` 是纯模拟层，不含 three.js：`step(state, dt, intents)` 在固定 `dt` 下推进墨水回复、部署、单位推进、目标选择、近战/投射物伤害、死亡清理与胜负判定。单机和房主跑同一份代码，客户端只渲染快照，因此不存在「单机合法、联机非法」的分叉。

每一帧单位会在**同车道、前进方向**上找最近的敌方单位；进入射程就停下开火（近战直接扣血，弓手生成一枚纸团投射物），否则继续推进。若前方没有敌人，目标就是敌方基地。投射物沿车道飞行，碰到敌方单位或基地才结算伤害。基地 HP 归零即终局。

敌方 AI 也在 `rules.js`：按玩家单位造成的压力评估三条车道，**大多数时候**补压力最大的一路，但有 32% 概率随机分路——全知式反制会把战线永远钉在玩家半场，后期关卡就变得不可赢。选兵也不再是随机：它会读目标车道上玩家的兵种，遇到橡皮盾/巨兽就挑高 dps 的印章破甲，遇到回形针弓手就派又快又耐打的兵突脸，空道则优先快速推进，同时仍受当前墨水约束。

难度曲线靠四件事单调上升：敌方部署间隔 `3.2s → 1.8s`、敌方墨水系数 `0.75 → 1.28`、敌方基地 HP `55 → 145`，以及第 6 关起 `26s → 18s` 一轮的怪潮爆发；玩家墨水回复只从 `1.15` 缓慢升到 `1.35`，第 7 关还会刻意回落。用三种玩家策略（只铺便宜兵 / 轮换 / 肉盾+弓手+巨兽）各模拟三轮：1–4 关稳赢，第 5 关起「只铺便宜兵」基本失效、必须换兵种，6–10 关每种策略约 1/3 胜率，Boss 关三种策略都能赢也都会输。

## 视觉

沿用 `doodletank` 的正交 `InkRenderer`（本作 20° 俯角，让墨水瓶和印章有立体感）：场景先渲进数据缓冲（明暗 / 墨色 id / 法线 + 深度），再由全屏 pass 画轮廓、排线、纸纹、横格线和红色装订线。车道分隔线与中央红线做成**较粗**的几何条——细条在宽视口下会掉到亚像素而整条消失（这是《墨水连珠》里踩过的坑）。左侧有五个装订孔。

四种印章各用一个 `InstancedMesh`（96 实例），队伍颜色通过 `instanceColor` 把墨色 id 传给 shader，所以一个网格就能同时画蓝军和红军；血条、纸团投射物同样用实例化。印章模型统一朝 `+X` 建模（铅笔尖头指向右），红方实例按行进方向 `u.dir` 绕 Y 轴旋转 180°，让尖头始终对着敌方，不会倒着走。两座墨水瓶会随剩余血量变矮。纸团投射物带一条朝后的锥形墨迹，红方实例同样按方向镜像。

攻击反馈全部由事件流驱动（`spawn / shoot / hit / die / surge / win`）：弓手开火时枪口炸一小圈墨点，近战与投射物命中会溅开墨点并留下短环，巨兽重击和基地受击会弹出上浮的伤害数字；打中墨水瓶时还有更大的墨环与屏幕震动，己方基地挨打会泛起一抹淡红。阵亡时炸开橡皮屑，怪潮爆发有提示与音效，通关放一轮墨色礼花。因为一秒内可能落几十次攻击，特效每帧限量（射击 6 组 / 命中 12 组）、同类音效按 `55–400ms` 节流，`src/audio.js` 里的四个本作专用音效也刻意做得很轻。

## 技术架构

```
stampduel/
├── index.html          # importmap(three) + peerjs + canvas#c + #hud + main.js
├── style.css           # 作业本风格 UI + 印章栏
├── serve.py            # 本地静态服务器
├── Dockerfile / docker-compose.yml
├── vendor/             # three.module.js + peerjs.min.js
└── src/
    ├── main.js         # 状态机、菜单、单机/联机、单击部署、结算
    ├── rules.js        # 纯模拟：墨水、单位、投射物、基地胜负、敌方 AI / 怪潮、快照编解码
    ├── units.js        # 四种印章数值表
    ├── waves.js        # 10 关配置与联机预设
    ├── scene.js        # 三车道、墨水瓶、印章实例化与血条
    ├── hud.js          # 基地血量、墨水条、印章栏、菜单/结算
    ├── pointer.js      # 单击射线 + 1–4 快捷键（复用）
    ├── render.js       # 正交 InkRenderer（复用）
    ├── effects.js      # 墨点/橡皮屑特效（复用）
    ├── audio.js        # 程序化 8-bit 音乐音效（复用）
    ├── net.js          # PeerJS 大厅与消息层（复用，独立命名空间）
    └── util.js         # 小工具（复用）
```

联机消息：`intent`（部署的车道与印章）/ `snap`（15Hz 全量快照：单位 `id,team,lane,x,hp,type` + 墨水 + 双方基地 HP + 事件流）/ `start`（开局或中途加入）/ `end` / `lobby` / `backtolobby`。客户端不跑模拟，只把单位位置按 `damp` 向快照目标插值，所以即使丢一两个包画面也不会跳。
